prepare_corpus.py scraper nahi hai. Yeh scraper se banne wali JSON files ko RAG ke liye ek consistent format mein jodti hai.

Script ka flow:
data/processed/ se profile sections, FAQs, reviews aur testimonials ki JSON files load karti hai.
Har record ko common fields deti hai: id, record_type, title, text, source_url, metadata.
FAQ mein question aur answer ko ek text field mein jodti hai; review ki rating, date aur reviewer metadata mein rakhti hai.
Sab records ko mila kar itc-corpus.json mein save karti hai.
Output mein 26 records aaye: 12 profile sections, 7 FAQs, 3 reviews aur 4 testimonials.

Iski zaroorat kyun pari?
Scraper ki alag files ka format alag tha—FAQ mein question/answer, review mein rating/date, aur profile mein section/text. Database aur baad ke chunking steps ko ek jaisa input chahiye. Yeh script woh farq normalize karti hai, aur record_type se pata chalta hai ke har record kis qisam ka content hai.

JSON files ko RAG ke liye ek consistent format mein jodti hai.

Iska matlab hai: alag JSON files mein data alag tareeqe se likha hota hai. Misal ke taur par:
- FAQ: question, answer
- Review: reviewer, rating, text
- Profile: section, text
Script in sab ko ek jaisi fields wale records mein badalti hai—jaise id, record_type, title, text, source_url, metadata.

Yani FAQ, review aur profile content apni pehchan rakhte hain, lekin unka overall format ek jaisa ho jata hai. Isse baad mein database mein save aur search karna aasaan hota hai.
