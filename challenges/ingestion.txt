
Flow:

corpus.json ke 26 structured records
        ↓
Markdown: title, type aur --- record boundaries
        ↓
documents.content mein ek webpage ka Markdown
        ↓
Apna splitter: records ko chunks mein baanta
        ↓
PostgreSQL chunks table: 63 rows
        ↓
vectorize.py: chunk ID, text aur metadata uthata hai
        ↓
Pinecone ka llama-text-embed-v2 embedding banata hai
        ↓
Pinecone index: vector + ID + metadata rakhta hai


Step by step:

1. Markdown ko chunking ke liye structure diya
   Corpus JSON ke har record ko title aur type mila; records --- se alag hue. Isse FAQ, review aur testimonial ki boundaries pehchanna aasaan hua.
2. PostgreSQL ke document content ko chunks mein baanta
   Splitter pehle --- par records alag karta hai. 500 characters tak ka record ek chunk rehta hai; lamba record sentence boundaries par split hota hai. Har chunk mein uska title/type context rehta hai. Overlap filhaal nahi rakha.
3. Chunks PostgreSQL mein save hue
   Har chunk ko integer ID aur chunk_index mila. Script ne 63 chunks save kiye. Dobara chalane par pehle us document ke purane chunks delete hote hain, phir naye save hote hain.
4. Pinecone index configure kiya
   Index ka naam medical-rag-chunks; deployment Serverless / On-demand, region AWS us-east-1. chunk_text field par integrated llama-text-embed-v2, 1024 dimensions aur cosine similarity set ki. title field hata di aur “Text isn’t kept” select kiya.
5. Chunks Pinecone mein bheje
   vectorize.py PostgreSQL se chunk ID, text aur metadata leta hai. Integer chunk ID ko string _id banata hai. Text Pinecone ko bhejna zaroori hai, taake uska model embedding bana sake; setting ki wajah se Pinecone text ko store nahi karta.
6. Pinecone mein metadata rakha
   document_id, chunk_index aur record_type jaise values record ke saath bhejte hain. Metadata ke liye alag predefined column/schema field ki zaroorat nahi. Source URL document row mein hai; chunk ke document_id se parent document mil sakta hai.
7. Upload confirm kiya
   Pinecone UI mein chunk IDs, metadata aur similarity search scores dikh rahe hain. Integrated embedding setup mein raw vector values UI mein dekhna zaroori nahi; Pinecone un par search kar raha hai.
Jina API key abhi is flow mein use nahi ho rahi. Humne Jina se Pinecone ke integrated model par switch kiya, kyunki BYOV option tumhare setup mein paid dikh raha tha. Documents aur future queries dono par Pinecone ka wahi Llama model lagega.


Challenges aur solutions


1- Records ka text flattened tha, boundaries saaf nahi thin → Markdown headings aur --- separators add kiye.
2- Pehla chunking function samajhne mein mushkil aur size bara tha → Approach simplify karke 500-character target aur sentence boundaries rakheen.
3- Pinecone schema mein metadata column nahi tha → Metadata fields ko har upserted record ke saath bhejne ka faisla kiya.
4- title Pinecone schema mein tha, lekin use ki zaroorat nahi thi → title field hata di.
5- BYOV selection paid thi → Pinecone ka integrated llama-text-embed-v2 use kiya; Pinecone khud embedding banata hai.
6- Database chunk IDs integers hain, Pinecone record IDs strings maangta hai → Upload ke waqt ID ko string _id banaya.
